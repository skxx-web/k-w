# K web — бот обслуживания сайтов

Бот работает как отдельный Cloudflare Worker с D1. Он не меняет код сайта и не использует существующий `kxxweb-edge`. Бинарные копии чеков остаются в Telegram: бот копирует их в закрытую архивную группу, а в D1 хранит ссылку Telegram и журнал решения администратора. Отдельное хранилище R2 не требуется.

Интерфейс — стандартные сообщения и кнопки Telegram на русском языке. Тон и обозначение K web следуют текущему сайту; цвет кнопок задаёт сам Telegram-клиент.

## Что умеет бот

- Список клиентов и сайтов; добавление клиента и сайта; изменение контактных данных, адреса, цены и даты обслуживания; архивирование записей.
- Клиентская заявка собирает имя, телефон, e-mail, сайт и описание; Telegram-ник берётся автоматически из Telegram. Числовой Telegram ID остаётся только внутренней технической связью и не показывается в формах.
- Администратор открывает заявку и нажимает «Создать профиль и открыть доступ», затем добавляет сайт, ежемесячную цену и дату оплаченного периода. После сохранения кабинет связывается с Telegram-аккаунтом заявки и клиент получает уведомление.
- После открытия доступа клиент получает приветствие и короткий статус подписки. В кабинете клиент видит только приветствие, активность/дату окончания подписки и кнопку проверки; телефоны, username и e-mail в клиентский экран не выводятся.
- Администратор может открыть «Предпросмотр клиента» из своего меню, чтобы увидеть клиентское приветствие, статус и экран реквизитов без второго аккаунта. Предпросмотр не отправляет сообщений клиентам и не принимает файлы/оплату.
- Администратор управляет банковскими данными кнопкой «Мои реквизиты». Клиент запрашивает оплату, видит текущие реквизиты, нажимает «Предоставить изображение или файл» и отправляет фото, изображение или PDF.
- После отправки чека бот присылает администратору в личный чат сам файл/изображение с данными заявки и кнопками подтверждения/отклонения. Клиент не может вести произвольную переписку; платёжный файл должен быть изображением или PDF.
- Чек сам по себе не меняет статус оплаты и не продлевает сайт. Администратор вручную проверяет поступление денег и подтверждает оплату.
- Подтверждение/отклонение чека, журнал событий, история оплат, CSV и JSON-резервная копия для администратора.
- Ежедневные напоминания за 3 дня до окончания оплаченного периода, в последний оплаченный день и на следующий день. Дедупликация ведётся по сайту, дате окончания и этапу напоминания.

Часовой пояс по умолчанию — `Europe/Moscow`, напоминания запланированы на 09:00 МСК (06:00 UTC). Если оплата подтверждена до конца периода, следующий месяц считается от прежней даты окончания. Если период уже истёк — новый месяц начинается от текущей даты. Крайние числа месяца ограничиваются последним днём целевого месяца.

## Секреты и первичная настройка Telegram

В GitHub хранятся только исходники и имена переменных. Токены и Telegram ID размещаются только в **Cloudflare Dashboard → Workers & Pages → `kweb-service-bot` → Settings → Variables and Secrets**, тип **Secret**:

- `TELEGRAM_BOT_TOKEN` — токен нового бота, полученный у `@BotFather`.
- `TELEGRAM_ADMIN_IDS` — Telegram ID администратора (или ID через запятую для нескольких администраторов).
- `TELEGRAM_WEBHOOK_SECRET` и `SETUP_KEY` уже создаются отдельно при развёртывании и не должны публиковаться.

Не отправляйте `TELEGRAM_BOT_TOKEN` в обычный чат и не коммитьте его в GitHub. После сохранения секретов нужно выполнить защищённое подключение webhook. Затем откройте бота от имени администратора и отправьте `/start`.

Задайте или измените данные для оплаты в боте: **/start → «Мои реквизиты» → «Добавить/Изменить реквизиты»**. Реквизиты хранятся в приватной настройке D1 и не пишутся в журнал значением; после изменения клиентам сразу будут показаны новые данные.

Для архива создайте **закрытую** Telegram-группу, добавьте туда бота и отправьте в группе команду `/setarchive` от имени разрешённого администратора. Проверьте, что бот может отправлять сообщения и копировать файлы. В группе будут видны данные клиента, e-mail, сайт, статус/последняя оплата и копии чеков, поэтому доступ к ней нужно ограничить только нужными людьми.

## Развёртывание

В аккаунте Cloudflare используются отдельные ресурсы:

- Worker: `kweb-service-bot`;
- D1: `kweb-service-bot-prod`;
- Cron `0 6 * * *` для ежедневных напоминаний и `*/10 * * * *` для очереди сообщений.

Команды из этой папки:

```sh
npm install
npm test
npx wrangler d1 migrations apply kweb-service-bot-prod --local
npx wrangler d1 migrations apply kweb-service-bot-prod --remote
npx wrangler deploy
```

Перед remote-командами требуется Cloudflare API-токен с правами создания Workers и D1, который передаётся Wrangler через переменную окружения. Не включайте токен в команду, конфигурацию или репозиторий. Подробности о webhook setup и секретах находятся в `SETUP.md`.

## Резервные копии

Команда `/backup` отправляет администратору JSON-снимок таблиц и CSV-список услуг в приватный чат Telegram. Скачать файлы на компьютер нужно вручную и положить в закрытую папку `Работа`, например `Работа/Архив сайта/`. Архивная группа не заменяет резервную копию: периодически скачивайте файлы вне Telegram и ограничивайте доступ к ним.

## Персональные данные

D1 хранит телефоны, Telegram ID, сайты, даты и историю операций. Архивная группа получает заявки и копии чеков. Не добавляйте в группу посторонних. В журнал Worker не записываются полные входящие сообщения или секреты. Удаляйте данные клиентов, если они больше не нужны, с учётом собственных сроков хранения и правил, применимых к вашей работе.

**Расположение данных:** Cloudflare D1 предлагает юрисдикции EU, US и FedRAMP, но не Россию. До внесения персональных данных реальных российских клиентов проверьте требования локализации, применимые к вашей деятельности. Если требуется хранение именно в РФ, не используйте эту D1-базу для таких данных — понадобится российское хранилище или другой согласованный вариант.

## Проверки

`npm test` проверяет даты, продление при просрочке, календарные границы, напоминания, суммы, URL и защиту CSV от формул. Полные проверки webhook, реального Telegram-бота, доставки в архивную группу и расписания требуют BotFather-токена и ID администратора/группы; они не считаются пройденными, пока не выполнены на подключённом боте.
