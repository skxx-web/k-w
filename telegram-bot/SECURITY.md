# Безопасность и тестирование

- Telegram webhook принимает POST только с корректным `X-Telegram-Bot-Api-Secret-Token`; `SETUP_KEY` защищает отдельную регистрацию webhook.
- Все команды, callbacks, резервные копии и CSV проходят повторную проверку ID администратора на сервере.
- Webhook update и callback-действия идемпотентны. Денежные изменения сохраняются отдельными append-only событиями.
- Чек создаёт только статус `pending`; автоматического подтверждения оплаты по файлу нет.
- SQL использует D1 prepared statements; имя/телефон/адрес ограничиваются по длине. Текст выводится без HTML parse mode.
- Outbox имеет уникальный ключ, блокировку с lease и повторную попытку с задержкой; сообщение не считается доставленным до ответа Telegram API.
- Cron использует календарные даты `Europe/Moscow`, а ключ напоминания включает сайт, дату окончания и тип напоминания.
- Резервные копии и CSV доступны только администратору. CSV защищает ячейки от формул.
- Не логировать bot token, URL Bot API, сырой webhook JSON, чеки и телефоны.

Перед эксплуатацией требуется проверить: неправильный webhook secret; повторный update; callback от неадминистратора; повторное подтверждение платежа; сбой архивирования; D-3/D0/D+1; просроченное продление; переход через конец месяца; безопасный backup/CSV; недоступность Telegram API и повтор outbox.
