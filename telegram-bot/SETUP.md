# Первичное подключение бота

1. Создайте бота у `@BotFather` командой `/newbot` и скопируйте выданный токен. Если бот уже существует, используйте его текущий токен; при подозрении на утечку сначала перевыпустите его у BotFather. Узнайте числовой Telegram ID администратора, например через `@userinfobot`.
2. Не отправляйте токен в этот чат и не добавляйте его в исходный код. Так как вход в Cloudflare Dashboard может быть недоступен, временно добавьте в GitHub **Settings → Secrets and variables → Actions** два encrypted repository secret: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_IDS`. `CLOUDFLARE_API_TOKEN` уже должен быть задан в репозитории. Не публикуйте секреты в issue, скриншотах или обычных сообщениях.
3. Запустите вручную workflow **Actions → Configure Telegram bot Worker secrets → Run workflow**. Он передаст значения напрямую в Cloudflare Worker Secrets; сами значения не выводятся в журнале и не попадают в Git. После успешной проверки временные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_IDS` можно удалить из GitHub Secrets, оставив их только в Cloudflare. `TELEGRAM_WEBHOOK_SECRET` и `SETUP_KEY` уже хранятся в Cloudflare — не заменяйте их.
4. После подтверждения, что Worker получил secrets, вызовите защищённую операцию регистрации webhook. Она использует скрытый `SETUP_KEY`; его не нужно отправлять в чат. Результат проверяется через Telegram `getWebhookInfo` без вывода токена.
5. Откройте личный чат с ботом и отправьте `/start`. Убедитесь, что меню администратора открывается у администратора. Клиенты не видят числовой Telegram ID в форме: бот сам получает Telegram-ник, а внутренний ID хранит только для закрытой связи с аккаунтом.
6. Создайте закрытую группу для архива, добавьте в неё бота (через его username из BotFather) и отправьте в группе `/setarchive` от имени администратора бота. Бот отправит тестовое сообщение в группу. Участниками группы должны быть только люди, которым разрешено видеть заявки, контакты и чеки.
7. Проверьте onboarding: тестовый клиент в личном чате нажимает `/start` → «Оставить заявку» и вводит имя, телефон, e-mail, сайт и описание. В админском меню откройте «Заявки» → выберите заявку → «Создать профиль и открыть доступ», затем заполните сайт, тариф и дату оплаченного периода. После сохранения клиент получит сообщение об открытии кабинета.
8. Проверьте клиентский «Мой кабинет»: он показывает срок обслуживания и последнюю подтверждённую оплату. Кнопка оплаты просит выбрать сайт и затем принимает только фотографию или PDF; обычные сообщения не отправляются как чат. Чек появится в закрытой архивной группе вместе с данными клиента, сайтом, последней оплатой и отметкой «ожидает проверки».
9. Подтвердите оплату только после проверки фактического поступления денег. Проверьте, что клиент получил результат, кабинет показал новый период, а группа получила событие подтверждения. Повторное нажатие не должно продлить подписку второй раз.

Перед добавлением данных реальных клиентов проверьте применимые требования к локализации: эта D1-база создана в регионе EEUR, а Cloudflare D1 не предоставляет российскую юрисдикцию хранения.

## Проверка перед реальными клиентами

- Создать тестовую заявку с Telegram username и e-mail; открыть доступ только после ручного действия администратора.
- Создать тестовый сайт с датой окончания через 3 дня; убедиться, что дневной Cron создаёт только одно напоминание.
- Отправить фото/PDF чека из кабинета и убедиться, что статус остаётся `pending`, а оплаченный период не меняется; проверить, что текстовый файл или произвольное сообщение не принимается как чек.
- Нажать «Подтвердить оплату» после фактической проверки; убедиться, что клиент получил сообщение, дата продления и платёжная запись изменились один раз, а старые напоминания отменены.
- Повторить update/callback и убедиться, что нет повторного продления или повторной записи.
- Проверить доступ к `/backup`, CSV и административным кнопкам с неадминистраторского аккаунта.

Не принимайте оплату автоматически по изображению чека. Чек — только заявка на проверку.
