# Первичное подключение бота

1. Создайте бота у `@BotFather` командой `/newbot` и скопируйте выданный токен. Если бот уже существует, используйте его текущий токен; при подозрении на утечку сначала перевыпустите его у BotFather.
2. В Cloudflare откройте **Workers & Pages → `kweb-service-bot` → Settings → Variables and Secrets**. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_IDS` как **Secret**. В ID укажите только числовой Telegram ID; несколько ID разделяйте запятыми. Не публикуйте токен в GitHub, issue, скриншоте или обычном сообщении.
3. После сохранения секретов вызовите защищённую операцию регистрации Telegram webhook. Она использует `SETUP_KEY`, сохранённый как Cloudflare Worker Secret; это значение не нужно отправлять в чат. В текущем развёртывании операцию можно выполнить безопасным служебным запросом из управляющей среды проекта. Результат проверяется через Telegram `getWebhookInfo` без вывода токена.
4. Откройте личный чат с ботом и отправьте `/start`. Убедитесь, что меню администратора появляется только у ID из `TELEGRAM_ADMIN_IDS`.
5. Создайте закрытую группу «Архив», добавьте бота с правом отправки сообщений и выполните `/setarchive` от имени администратора. Бот подтвердит подключение. Проверьте архив тестовой заявкой и тестовым чеком до реального использования.

## Проверка перед реальными клиентами

- Создать тестового клиента и сайт с датой окончания через 3 дня; убедиться, что дневной Cron создаёт только одно напоминание.
- Отправить чек и убедиться, что статус остаётся `pending`, а оплаченный период не меняется.
- Нажать «Подтвердить оплату» после тестовой проверки; убедиться, что дата продления и платёжная запись изменились один раз, а старые напоминания отменены.
- Повторить update/callback и убедиться, что нет повторного продления или повторной записи.
- Проверить доступ к `/backup`, CSV и административным кнопкам с неадминистраторского аккаунта.

Не принимайте оплату автоматически по изображению чека. Чек — только заявка на проверку.
